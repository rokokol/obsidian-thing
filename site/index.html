What the agent gets

Reading, writing, search and links, on one address

One vault does not offer the tools of another: the server shows a client only what the configuration of that vault allows

reading

A file, its revision and its links

obsidian.read returns the text and its SHA-256, and obsidian.stat returns the size and the revision without the bytes. A separate graph counts links, backlinks and attachments, without Obsidian

  • Canvas and Base read as documents
  • Link resolution with anchors and ambiguity
  • A 1 MiB limit on UTF-8 text
 writing

Replace, edit a fragment, rename

Writing is off by default. In a writable vault it is an atomic replacement at a revision, and rules or a Python checker can reject the proposed text before it reaches disk

  • obsidian.update replaces one exact fragment
  • A rename updates the visible links
  • Deletion only to a private trash
 search

Text, metadata, vectors

Full-text search works with no model. obsidian.find filters by tag, alias, property and file name. Embeddings add semantics, neighbours and a map of the neighbourhood

  • Index and cost journal outside the vault
  • Ollama, LM Studio, OpenRouter or your own endpoint
  • obsidian.status reports coverage and cost
 integrations

What lives only in Obsidian

Structural edits of Canvas and Base, Iconic file icons, FSRS Vocabulary cards and Excalidraw export to PNG. Each integration is a switch on a vault, and almost every one is off by default

  • The document is validated before it is published
  • One failed change leaves the file as it was
  • A PNG render without the app
Skills, memory, instructions

The vault brings its own rules, and its own skills

An agent needs three things that are not notes: the rules of the vault, the skills written for it, and what earlier sessions learned. All three sit in hidden paths, which a plain read never reaches. The server serves them by name, beside the skills the agent already carries

  1. Instructions come first

    obsidian.agentsmd returns the first readable file of the configured list, so AGENTS.md never hides behind GEMINI.md, and a file outside the allowlist never hides one inside it

  2. The vault's skills, read by name

    obsidian.skills_list lists .agents/skills with each name, description and SKILL.md path. obsidian.skill_read reads the skill and its reference files

  3. Memory outlives the session

    obsidian.memory_read and memory_list read the notes in .agents/memory, and memory_write writes a note and its line in MEMORY.md, in a writable vault only

How a call runs

Four steps, each one checked

The server holds no session: every call carries its token and passes the same checks

  1. The client names the endpoint and the token

    POST /vaults/notes/mcp with Authorization: Bearer. Another token gets 401, an unknown vault 404, an unlisted Host 421

  2. The vault checks the path against the allowlist

    A file allows itself alone and a directory allows its subtree. A hidden segment, a symlink and an escape from the root are refused at every step

  3. The tool does the work

    A read comes from disk, a search from the local index, and a write goes to a temporary file with its checks before the replacement

  4. The answer names the revision

    The new revision is the SHA-256 of what is on disk now. The next write must name it, or the server refuses instead of guessing

Install

One process, one TOML file

Copy config.example.toml, name the vault and the paths it serves, and put the token in an environment variable. The rest is in the guide

From the flake

A build that never asks a registry: the package and the Docker image come from one derivation

nix run github:rokokol/obsidian-thing -- --config config.toml

From a checkout

Python 3.11 or newer. The file watcher exists on Linux; other systems reconcile the index by periodic scans

uv run --locked obsidian-thing --config config.toml

An image from the same package

The image needs no Nix at runtime. The vault and the configuration mount read-only, and the state is a separate directory

docker run --rm --read-only --publish 127.0.0.1:8765:8765 --env OBSIDIAN_THING_NOTES_TOKEN --volume "$PWD/config.toml:/config.toml:ro" --volume /srv/notes:/vault:ro obsidian-thing:local --config /config.toml --host 0.0.0.0

The NixOS module

The module writes the configuration, creates the private state directories and runs the service as an unprivileged user

obsidian-thing.enable = true;
