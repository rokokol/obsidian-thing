Connect a client

Four steps to the first call. Everything below was run against a live server, and the exact key names are in the reference

Canonical source: docs/config.md and docs/deployment.md

1. Name the vault

The vault table is named after its ID, and that name becomes the last segment of the endpoint

[vaults.notes]
root = "/srv/notes"
allowed = ["."]
token_env = "OBSIDIAN_THING_NOTES_TOKEN"

[vaults.notes.embeddings]
enabled = false
state_dir = "/var/lib/obsidian-thing/notes"

A . in allowed opens the whole vault. Name the paths one by one when the agent needs only a part of it. The state directory is required for search, and it must be private

2. Set the token

The name comes from token_env and the value is the token itself. It accepts ASCII letters, digits and the characters ._~+/=-

export OBSIDIAN_THING_NOTES_TOKEN=$(openssl rand -hex 32)

3. Start the server

nix run github:rokokol/obsidian-thing -- --config config.toml

Without Nix: uv run --locked obsidian-thing --config config.toml. The default address is 127.0.0.1:8765, and the server prints it at start

4. Point the client at the endpoint

The client needs the address and an Authorization header. The shape below is what most clients accept; substitute the token, or your client's own variable syntax

{
  "mcpServers": {
    "notes": {
      "type": "http",
      "url": "http://127.0.0.1:8765/vaults/notes/mcp",
      "headers": {
        "Authorization": "Bearer <token>"
      }
    }
  }
}

The first call

The server is stateless, so one command checks the whole path. The answer carries the path, the text and the revision

curl -sS http://127.0.0.1:8765/vaults/notes/mcp -H 'Content-Type: application/json' -H 'Accept: application/json, text/event-stream' -H "Authorization: Bearer $OBSIDIAN_THING_NOTES_TOKEN" -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"obsidian.read","arguments":{"path":"Notes/Hello.md"}}}'

The revision is the SHA-256 of the file bytes. The client remembers it and names it on the next write

Deployment

Behind a reverse proxy the host name belongs in allowed_hosts, and the proxy forwards Authorization unchanged. A container needs --host 0.0.0.0, because it listens on loopback by default

docker run --rm --read-only --user "$(id -u):$(id -g)" --publish 127.0.0.1:8765:8765 --env OBSIDIAN_THING_NOTES_TOKEN --volume /srv/config.toml:/config.toml:ro --volume /srv/notes:/vault:ro obsidian-thing:local --config /config.toml --host 0.0.0.0

The NixOS module writes the configuration from settings, creates the private state directories and runs the service as an unprivileged user

The Obsidian plugin

  1. Download manifest.json, main.js and styles.css from one release, put them in .obsidian/plugins/obsidian-thing/, then enable the plugin under Community plugins
  2. In the settings, enter the full endpoint, including /vaults/<vault_id>/mcp. Outside a trusted network use HTTPS only
  3. Paste the token into the storage field: the plugin writes it to Obsidian's secret storage and keeps only the secret ID in data.json
  4. Press Test: the plugin shows the tools the server offers this vault, and hides the rest

The plugin keeps no index and edits no notes. Search, neighbours, the map and the status come from the server's index, and only the server can call a provider
