Features

What the server does, and where it stops

Each capability is switched on separately and applies to one vault. What is off never appears in the tool list and costs nothing

Reading

Text, revision and the graph of links

A file with its revision

obsidian.read returns the path, the content and the SHA-256 of the bytes. obsidian.stat returns the size and the revision without moving text

Links, both ways

obsidian.links_out lists the links of a note, Canvas or Base with each resolution, and obsidian.links_in lists what points at a file

Attachments without bytes

obsidian.media names the attachments, their type and their size, and returns no file bytes

How a link resolves
Status Meaning
resolvedOne file, and its anchor exists
ambiguousMore than one file matches. The server returns the candidates and gives none of them the backlink
unresolvedNo visible file matches
externalThe link points outside the vault. The server does not fetch it
Writing

Replace at a revision, edit a fragment, rename

Writing is off by default. In a writable vault it is serialized in one process, and it does not protect against an unsaved buffer in Obsidian

create and replace

One atomic write

A new file is created without expected_revision. A replacement must name the revision, or the server refuses with a read-first error

fragment

One exact match

obsidian.update replaces old with new where old occurs exactly once. Two matches, overlapping ones included, refuse the edit

rename

Links change with the name

The file stays in its directory with its extension. Visible links change in the same step, and one unsafe edit cancels the whole rename

Deletion needs a configured trash, and it refuses when a note would lose a link target. See permissions

Rules

A written rule is checked before the write

Each check compares the current file with the proposed text. What the file already had becomes a warning, and a new finding becomes an error that blocks the write

The per-vault checks
Key What it checks Level
default_quotesThe quotes of new text, for example ""error
trailing_periodsA full stop at the end of a paragraph or a list itemerror
broken_linksA new link with no targeterror
calloutsAn unknown callout markererror
paragraph_linesA paragraph broken into lines by handwarning
prevent_inline_tagsA new inline tag in Markdownerror
bases, canvasThe structure of a Base and a Canvaserror

Your own linter for the vault

The built-in checks cover quotes, periods and links. Anything else your vault asks for — a naming scheme, a required property, a tag that must not appear, a section that must be there — is a Python script. It sees the proposed text, its links and the properties you select, and answers allow, warn or refuse with a reason

A refusal instead of a damaged file

A timeout, a non-zero exit, a malformed answer or more than 16 KiB of output blocks the write. The checker cannot return replacement text, and it does not take part in a deletion

Search

Text without a model, meaning on request

The index lives in a private state directory outside the vault, and the cost journal lives in a database of its own inside it

text

Ranking with no provider

obsidian.query searches words through FTS5 and needs no model. Underscores stay inside a word, so section_chunks is found

metadata

Filters on properties

obsidian.find filters by tag, alias, property and a regular expression on the file name, with no embeddings. A tag matches its descendants

vectors

Neighbours and a map

obsidian.related finds the nearest notes to a file or one of its sections, and obsidian.map draws the same neighbourhood on two axes. The vectors rank, the coordinates do not

Integrations

What Obsidian keeps in its own formats

Almost everything is off by default. A switch on adds its tools, and a switch off neither scans nor rewrites its references

Skills, memory, instructions

The vault brings the agent its own rules

01

Instructions by name

obsidian.agentsmd returns the first readable file of instructions, by default AGENTS.md, GEMINI.md, CLAUDE.md. A file outside the allowlist is skipped and never hides the next one

02

Skills beside the agent's own

obsidian.skills_list reads .agents/skills, and obsidian.skill_read opens SKILL.md and the reference files inside the skill directory. The harness skills and the vault skills never collide

03

Memory that outlives the session

A note in .agents/memory with a description in its frontmatter takes one line in MEMORY.md. Only a writable vault can write one

The plugin

The server's answer, inside Obsidian

The plugin keeps no index of its own and edits no notes: it shows what the server computed and hides what the server does not offer

The sidebar

Search with filters, and a tab of the open note's neighbours, with the file opening from a result

The map

A separate view with the same neighbourhood on two axes. A point opens its note

The status

Index coverage, the queue, the model profile and the cost by day, with a confirmed price kept apart from an estimate
